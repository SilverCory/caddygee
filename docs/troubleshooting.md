# Troubleshooting

Common issues and how to fix them.

## `/deploy` returns 503

**Cause:** The deploy endpoint is disabled. This happens when `CONFIG_BUCKET` or `CADDYGEE_AUDIENCE` is not set on the running container.

**Check:** Verify the Cloud Run env vars:
```bash
gcloud run services describe caddygee \
  --region=<region> \
  --project=<caddygee-project> \
  --format='yaml(spec.template.spec.containers[0].env)'
```

Both `CONFIG_BUCKET` and `CADDYGEE_AUDIENCE` must be present. If missing, update via Terraform and apply.

---

## `/deploy` returns 401 Unauthorized

**Cause:** The OIDC token is missing, expired, or has the wrong audience.

**Check the audience:** The token must be minted for exactly the value of `CADDYGEE_AUDIENCE` on the running service (no trailing slash):
```bash
gcloud auth print-identity-token \
  --impersonate-service-account=<sa>@<project>.iam.gserviceaccount.com \
  --audiences="https://gateway.example.com"
```

**Check SA impersonation:** If you get `PERMISSION_DENIED: Failed to impersonate`, your user account needs `roles/iam.serviceAccountTokenCreator` on the service account:
```bash
gcloud iam service-accounts add-iam-policy-binding \
  <sa>@<project>.iam.gserviceaccount.com \
  --member="user:<your-email>" \
  --role="roles/iam.serviceAccountTokenCreator" \
  --project=<project>
```

IAM changes take 1–2 minutes to propagate.

---

## Container fails startup probe (exit 1)

Check the Cloud Run logs for the specific error:
```bash
gcloud logging read \
  'resource.type=cloud_run_revision AND resource.labels.service_name=caddygee AND jsonPayload.level=error' \
  --project=<caddygee-project> \
  --limit=5 \
  --format=json | python3 -c \
  'import json,sys; [print(l["jsonPayload"]["msg"]) for l in json.load(sys.stdin) if "jsonPayload" in l]'
```

### `failed to decode PEM block`

**Cause:** A `verify_jwt` fragment has a `public_key` with literal `\n` escape sequences instead of real newlines. This happens when a fragment was generated by an older version of the transpiler or hand-edited incorrectly.

**Fix:** Re-transpile with the current CLI (which uses backtick quoting), or manually fix the fragment. See [Fragment encoding notes](deploying-a-proxy.md#fragment-encoding-notes).

### `SyntaxError: ... Unexpected token ILLEGAL`

**Cause:** Same root cause — a `js_callout source` field has `\n` escape sequences instead of real newlines.

**Fix:** Re-transpile with the current CLI or fix the fragment manually.

### `loading module 'subroute': provision ...`

Caddy failed to provision the merged config. The full error in `jsonPayload.msg` will identify the exact module and route. Common causes:
- Invalid JWKS URI that doesn't resolve
- Missing required subdirective in a handler block
- Fragment left over from an old transpiler version with incompatible syntax

## `no routes configured` response from the gateway

**Cause:** caddygee started with its fallback Caddyfile — no fragments were loaded. This means either:
- The GCS bucket is empty (no fragments deployed yet)
- caddygee-server failed to fetch from GCS on cold start (check logs for `cold-start merge failed`)

**Fix:** Deploy at least one fragment via `/deploy` or upload fragments to GCS directly, then restart the service.

---

## `/deploy` path not reaching the deploy server

**Symptom:** A `POST /deploy` returns an unexpected response from Caddy rather than a deploy-specific status.

**Cause:** The Caddyfile running on the instance does not include `handle /deploy { reverse_proxy localhost:9090 }`. This directive is included automatically when using `caddygee merge --cloud-run` but would be absent in a manually constructed or outdated Caddyfile.

**Fix:** Regenerate the Caddyfile using `caddygee merge --cloud-run`, upload to GCS, then restart.

---

## SSL certificate stuck in PROVISIONING

**Cause:** The DNS record for the domain does not yet point to the load balancer IP, or DNS has not propagated.

**Check:**
```bash
# Check cert status
gcloud compute ssl-certificates describe caddygee-cert \
  --global \
  --format='value(managed.status,managed.domainStatus)'

# Check DNS resolution (should return your LB IP)
dig <your-domain> A +short
```

The cert activates automatically once DNS resolves to the load balancer IP. Allow up to 30 minutes after DNS propagation.

---

## Terraform apply fails with 403 on Firestore

**Cause:** The authenticated account lacks `datastore.databases.create` permission.

**Fix:** Create the Firestore database manually then import it into Terraform state:
```bash
gcloud firestore databases create \
  --location=<region> \
  --project=<caddygee-project>

terraform import google_firestore_database.default \
  'projects/<caddygee-project>/databases/(default)'
```

---

## `PORT` env var rejected by Cloud Run

**Symptom:** `terraform apply` fails with `The following reserved env names were provided: PORT`.

**Cause:** Cloud Run injects `PORT` automatically — it cannot be set manually.

**Fix:** Remove the `PORT` env var from the Terraform resource. Caddy listens on `LISTEN_ADDRESS` (`:8080`), not `PORT`.

---

## Checking what config Caddy is currently running

```bash
# The Caddy admin API is on localhost:2019 inside the container.
# Use Cloud Run proxy to reach it locally:
gcloud run services proxy caddygee \
  --region=<region> \
  --project=<caddygee-project> \
  --port=2019

# In another terminal:
curl http://localhost:2019/config/ | python3 -m json.tool | head -100
```
